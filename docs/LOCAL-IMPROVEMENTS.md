# 问搭 · 本地体验完善记录

> 2026-11-04 · 本轮范围：只用本地功能，不开通付费云开发，不发布上线

## 一、这轮改了什么

### 1. 意见反馈：原来只弹提示，内容直接丢了

**问题**：设置页「意见反馈」点确认后只弹一句「已收到，谢谢反馈」，
用户写的内容没有任何地方保存，等于石沉大海。

**现在**：
- 反馈真实落到本机存储（`saveFeedback` / `listFeedbacks`）
- 提示如实说明保存位置：「已保存到本机（第 N 条）」，不再假装已收到
- 设置页显示反馈条数，新增「我的反馈记录」入口可查看历史
- 空内容会被拒绝，且**不会**提示成功

### 2. 通知中心：已读状态不同步，重复进入会重复追加

**问题**：
- 拉取后自动标记已读，但界面上的未读红点数量仍是旧值
- 每次 `onShow` 都用当前 `page` 继续加载，第二次进入会把第 2 页追加到第 1 页后面，
  列表重复、且第 1 页缺失

**现在**：
- `refresh()` 每次进入都从第 1 页重新拉取，不再重复追加
- 自动已读后重新拉取未读统计，保证红点数量与列表一致
- 列表项同步标记 `read: true`，红点即时消失
- 「全部已读」后未读数同步归零
- 标记已读失败时**保持原状**，不谎报已读

### 3. 提问草稿：写到一半切走，内容全丢

**问题**：填了标题和描述后切出去（接电话、看别的 App），回来表单是空的，
几十个字要重打一遍。

**现在**：
- 新增 `services/draft.js`，输入时自动存草稿到本机
- 重新进入提问页自动恢复，并提示「已恢复你上次没写完的内容」，可一键清空
- 发布成功后自动清除草稿
- 草稿只存自己的一份，不动其他任何本地数据

### 4. 顺手修的

- `package.json` 里 `test:pages` 被定义了两次，后者覆盖前者。已拆成
  `test:pages`（页面逻辑）与 `test:routes`（页面注册）
- 通知开关文案原本写「新回答到达时提醒你」，但系统级推送并未实现。
  改为「在『消息通知』里标记提醒」，并加一行说明当前只有应用内提醒

### 兜底分析器为什么重写

原来的 `verify-error-handling.js` 只比 `.then` 和 `.catch` 的**数量**，
这会误判：一条链里可能有多个 then 只对应一个 catch（then 内部 return
另一个 promise 再 then）。

新版改为按**链结构**判定：括号配平找到链的真正末尾，
再区分「链末尾的 then（需要自己的 catch）」与「链中间的 then
（整条链有 catch 即可）」。

但光改完不算数——**如果分析器永远返回「通过」，它就是 useless 的守卫**。
所以加了 `verify-error-handling-selftest.js`，用 8 个人造样本反向验证分析器：

- 有 catch 的简单链 → 判为已兜底
- 无 catch 的简单链 → 判为有漏洞
- 链中间 then + 整链末尾有 catch → 判为已兜底
- 链中间 then + 整链也没 catch → 判为有漏洞
- 用 finally 兜底 → 判为已兜底
- 嵌套链内层有 catch → 判为已兜底
- 嵌套链内外都没 catch → 判为有漏洞
- 两个独立语句各自无 catch → 判为有漏洞

8 项全过，说明这个守卫是真的能用。

## 三、尚未验证的部分

诚实说明本轮**没有**做到的事：

1. **没有在微信开发者工具里逐页点过**。本轮新增的草稿提示、反馈条数、
   通知红点同步都只有 Node 层行为测试覆盖，真实界面效果未经人眼确认。
   （上一轮 IDE 实测显示 Errors: 0，但那是本轮改动之前的状态。）

2. **没有真机验证**。模拟器与真机的存储行为可能有差异
   （如 `wx.getStorageSync` 的容量限制、后台清理策略）。

3. **反馈没有云端存储**。云开发未开通，`saveFeedback` 目前只落本机。
   代码里已按「mock 与云端契约一致」预留了云函数 handler，
   但云端版本尚未实现，页面的 `source === 'local'` 判断即为如实标注。

4. **通知开关只是偏好记录**。三个开关目前只存设置、不产生真实提醒。
   文案已改为如实描述，但功能本身要等云开发接入后才可能真正生效。
