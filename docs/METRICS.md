# 问搭 · 验证指标与节奏

## 1. 北极星指标

**每周「被解决的问题数」** —— 即每周处于 `adopted` 状态的问题数量。

为什么不是 DAU：DAU 可以靠内容灌水刷出来，但「问题被解决」同时意味着
有人提了问题、有人认真回答了、提问者认可了。三个环节都通过，才是真实价值。

---

## 2. 核心指标

### 供给侧

| 指标 | 定义 | MVP 目标 | 说明 |
|---|---|---|---|
| 首答率 | 提问后 24h 内获得 ≥1 条回答的问题占比 | ≥ 45% | 最关键的冷启动指标 |
| 优质首答率 | 24h 内获得 ≥3 条回答 | ≥ 20% | 反映内容吸引力 |
| 回答转化率 | 日活中产生 ≥1 次回答行为的占比 | ≥ 25% | 反映供给意愿 |
| 人均回答数 | 日回答数 / 日活 | ≥ 1.5 | |

### 需求侧

| 指标 | 定义 | MVP 目标 |
|---|---|---|
| 提问转化率 | 日活中产生 ≥1 次提问的占比 | ≥ 10% |
| 采纳率 | 最终被采纳的问题占比 | ≥ 40% |
| 次周留存 | 首次使用后第 7 天仍活跃 | ≥ 20% |

### 裂变

| 指标 | 定义 | MVP 目标 |
|---|---|---|
| K 因子 | 平均每用户带来新用户数 | > 1.2 |
| 分享率 | 分享次数 / 问题浏览次数 | ≥ 8% |
| 分享转化 | 通过分享进入的用户 / 分享次数 | ≥ 12% |

### 内容健康度

| 指标 | 定义 | 目标 |
|---|---|---|
| 零回答问题占比 | `pending` 且超 24h 的问题占比 | ≤ 30% |
| 举报率 | 举报数 / (问题数 + 回答数) | ≤ 1% |
| 隐藏率 | 被隐藏内容 / 总内容 | ≤ 3% |

## 3. 验证节奏

### 第 0 周 · 纸面验证（写代码之前）

**目的**：验证「有没有人真的愿意回答陌生人的纠结」。

动作：
1. 从种子数据里挑 30 个问题，整理成一张帖子发到 50 人的微信群
2. 帖子里直接给出 3 个选项，邀请大家投票 + 说理由
3. 观察 48 小时

| 判定 | 标准 | 动作 |
|---|---|---|
| ✅ 通过 | 投票参与率 ≥ 15%，且 ≥ 5 人主动写了理由 | 继续写代码 |
| ⚠️ 边缘 | 投票 ≥ 8% 但几乎没人写理由 | 强化「给理由」的引导文案后重测 |
| ❌ 不通过 | 投票 < 8% | 重新定位问题类型，别写代码 |

**这一步花 2 天，但能省掉 2 个月的开发。**

### 第 4~6 周 · MVP 内测（50 人封闭）

**只验证一件事**：提问 → 被回答 → 采纳，链路是否通。

不做的事：不发版、不推广、不做运营活动。

| 观察点 | 判定 |
|---|---|
| 提问后多久收到第一条回答 | 中位数 < 6 小时为通过 |
| 提问者是否会采纳 | ≥ 40% 为通过 |
| 有没有人主动发新问题 | 每个测试用户 ≥ 1 个为通过 |
| 有没有人提垃圾内容 | > 5% 需加强内容引导 |

### 第 7~8 周 · 小范围公测（500 人）

开始看留存曲线。

| 指标 | 目标 |
|---|---|
| 次日留存 | ≥ 30% |
| 次周留存 | ≥ 20% |
| 首答率 | ≥ 40% |
| 分享率 | ≥ 5% |

**公测期需要做的**：每天人工投喂 1 个「今日一题」，并在 2 小时内给出高质量回答。
这是维持「真有人在答」感知的关键动作。

### 第 9 周起 · 正式发布

- 提审通过后上线
- 配 1 个渠道活动（见冷启动手册）
- 保持每日运营节奏至少 4 周

## 4. 数据埋点

### events 集合（已实现）

埋点模块：`miniprogram/services/tracker.js`
云函数：`qa` 的 `track` action，写入 `events` 集合。

```js
{
  _id: 'auto',
  openid: 'openid',
  event: 'question_view',   // 事件名
  targetId: 'q_xxx',        // 关联对象
  params: { cat: 'eat' },   // 附加参数
  createdAt: 1750000000000
}
```

**上报策略**（已实现）：
- 异步上报，绝不阻塞 UI
- 批量发送：攒够 10 条或超过 15 秒触发
- 失败回退：上报失败放回队列，下次重试（队列上限 50 条）
- mock 模式不发送，留在本地缓存等接通云环境

### 事件清单

| 事件 | 触发时机 | 用途 |
|---|---|---|
| `app_open` | 小程序启动 | 活跃 |
| `question_list_view` | 广场加载 | 曝光 |
| `question_view` | 打开详情 | 详情浏览率 |
| `question_publish` | 发布问题 | 供给 |
| `option_vote` | 投票 | 互动 |
| `answer_publish` | 发布回答 | 供给 |
| `answer_like` | 点赞 | 互动 |
| `answer_adopt` | 采纳 | 价值闭环 |
| `share_click` | 点击分享 | 裂变 |
| `share_enter` | 通过分享进入 | 裂变归因 |

> 埋点已在四个页面全部接入，自检脚本第 6 项会校验事件常量与页面接入情况。
> `share_enter` 需要在小程序 `onShow` 里读取 `query.scene` 区分来源，
> 这一项尚未接完，是 V2 的小尾巴。

## 5. 决策规则

### 什么时候该砍功能

上线 8 周后，若出现以下任一情况，**暂停功能开发，回到供给侧**：

- 首答率 < 25% → 问题不够好答，或分类太宽
- 次周留存 < 12% → 需求不成立或频次太低
- 分享率 < 3% → 缺乏自传播基因，需要加话题机制

**供给不达标时，加功能只会稀释注意力。**

### 什么时候该加功能

三个信号同时满足才加：

1. 首答率 ≥ 45%
2. 次周留存 ≥ 20%
3. 种子内容已消耗完（运营开始「编不出新问题了」）

这时候加分类、加位置、加 AI 草稿才有意义。
