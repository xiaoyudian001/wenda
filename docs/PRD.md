# 问搭 · 产品需求文档（MVP）

## 1. 产品定位

**一句话**：把生活里的选择困难，交给别人来回答。

**不是什么**：
- 不是知乎（不做长篇讨论、不做知识检索）
- 不是大众点评（不做商家信息与优惠）
- 不是投票活动（不只是一张票，要的是「有理由的建议」）

**是什么**：一个聚焦「日常选择」的轻量问答场。用户提一个具体的纠结，别人给出带理由的建议，提问者采纳后问题关闭。

---

## 2. 目标用户

| 人群 | 典型场景 | 核心诉求 |
|---|---|---|
| 独居/双人生活者 | 今天吃什么、买不买 | 快速拍板 |
| 通勤上班族 | 明天穿什么、午饭吃什么 | 降低决策疲劳 |
| parents（有娃家庭） | 周末去哪玩、孩子不听话 | 找到可复制的方法 |
| 礼赠场景用户 | 送什么给同事/朋友 | 避开雷区 |

**首期聚焦**：以「吃什么 / 穿什么 / 去哪玩 / 带孩子」四类切入，占种子内容的 72%。

## 4. 核心流程

### 4.1 提问流程

```
选择分类 → 写标题 → 补充说明（可选）→ 给选项（可选，强烈建议）→ 匿名开关 → 发布
```

约束：
- 标题 ≤ 50 字，必填
- 描述 ≤ 300 字
- 选项 ≤ 6 个
- 描述中可含预算、人数、忌口、时间等限制条件

**选项是这个产品最重要的设计**。带选项的问题回答成本极低（点一下），首答率显著更高。
产品内已明示：「带选项的问题平均能多拿到 3 倍回答」。

### 4.2 回答流程

```
查看问题 → 投票（选自己的选项，可改）→ 写回答（≤500字）→ 发布
```

- 每人每题对选项只能投一次（云端幂等）
- 回答可带一个「我选 X」的推荐标记
- 回答需给理由（产品文案引导，不做强制）

### 4.3 采纳流程

```
提问者在详情页 → 点「采纳这条」→ 二次确认 → 回答被标记 🏆 → 回答者积分 +10
```

- 只能采纳一条
- 只有提问者能采纳（云端校验 `asker._id === openid`）
- 采纳后问题状态变为 `adopted`

### 4.4 状态机

```
pending（待回答）
   ├─ 收到回答 ──→ answered（已有回答）
   │                    └─ 被采纳 ──→ adopted（已解决）
   └─ 运营隐藏 ────────────────────→ hidden
```

### V2 规划

- 位置：附近/同城玩法
- 决策复盘：已解决问题串成个人时间线
- 答案海报：生成可分享的图
- 话题/挑战赛
- 回答评论

### V3 规划

- 付费「急答」
- 会员权益
- AI 辅助生成答案草稿（仅草稿，不代替真人）
- 团队/家庭空间

## 6. 页面说明

### 6.1 广场 `pages/index/index`

```
┌─────────────────────────────┐
│ 问搭                        │  橙色头图
│ 把选择困难，交给别人          │
├─────────────────────────────┤
│ ✨全部 🍜吃什么 👕穿什么 🎈去哪玩… │  横向滚动分类
├─────────────────────────────┤
│ 🔥最热  🕐最新  ⏳待回答       │  排序切换
├─────────────────────────────┤
│ ┌─────────────────────────┐ │
│ │ [买不买] 📍天津           │ │
│ │ 空气炸锅值得买吗            │ │
│ │ 厨房小张                   │ │
│ │ ▓▓░ 买      17%          │ │  选项条
│ │ ▓░░ 不买    14%          │ │
│ │ ▓▓▓ 看需求  55% ✓        │ │
│ │ 💬2回答 📊94人选  🏆已解决  │ │
│ └─────────────────────────┘ │
└─────────────────────────────┘
```

卡片只展示前 3 个选项（按票数排序），完整选项进详情页。

### 6.2 详情 `pages/detail/detail`

- 顶部：返回 / 标题 / 分享
- 问题区：分类标、城市、标题、描述、**全部选项可投票**、提问者
- 回答区：按「已采纳 → 点赞数」排序，每条含头像、昵称、时间、推荐项、点赞、采纳按钮
- 底部固定操作条：分享 / 写回答
- 写回答：底部弹出面板，500 字上限

### 6.3 提问 `pages/ask/ask`

分区表单，每组带引导文案。选项可增删（最多 6 个）。

### 6.4 我的 `pages/mine/mine`

- 渐变头部：头像、昵称、积分、已解决数
- 三宫格统计：我的提问 / 我的回答 / 被采纳
- 功能菜单：我的提问、我的回答、我的采纳、我的收藏、决策复盘
- 设置区：设置、隐私与安全、意见反馈、重置本地演示数据

## 8. 非功能要求

- **性能**：广场首屏 ≤ 1.5s（云函数分页 + 索引）
- **降级**：云函数不可用时自动切本地 mock，任何环境都可演示
- **安全**：文字过 `msgSecCheck`；举报入口覆盖问题与回答；管理员操作需 role 校验
- **隐私**：匿名提问时隐藏昵称与头像；不采集位置（V2 才做）
- **合规**：需企业/个体户主体认证；类目建议选「工具-信息查询」或「生活服务-社区/论坛」

## 9. 待决策事项

1. **主体资质**：是否已有公司/个体户？涉及微信认证与支付能力。
2. **运营人力**：能否每天人工投喂内容和答疑？没有的话需要 AI 辅助草稿方案。
3. **商业化优先级**：急答付费 / 会员 / 纯广告。
4. **名称**：微信名称审核严格，建议准备 2~3 个备选（「问搭」「问个搭」「替我拿主意」）。
